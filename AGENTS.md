# AGENTS.md — tinyimg

CLI-компрессор PNG/JPEG/WebP в зоне качества TinyPNG. Go, ноль зависимостей
(единственное исключение — libwebp через cgo, согласовано с пользователем).
Приёмка качества — глазами пользователя; гейты — против TinyPNG.

## Команды

```sh
go build -o tinyimg ./cmd/tinyimg    # сборка CLI
go test ./... && go vet ./...                # тесты + линт
./tinyimg research/orginal -o research/output   # прогон корпуса
```

Гейты (размер ≤ +20% к TinyPNG, SSIM ≥ TinyPNG − 0.02): харнесс живёт в
`research/tool/` (отдельный go-модуль):

```sh
cd research/tool && go build -o /tmp/imgresearch .
cd research && /tmp/imgresearch orginal compressed_by_tinypng output
# -> report.json / report.md: пары, метрики, гейты
```

## Структура

- `cmd/tinyimg/` — CLI-оболочка: флаги, вывод, коды возврата 0/1/2
- `cmd/tinyimg-web/` — веб-сервис (upload → compress → download/zip);
  результаты в памяти с TTL 1 час; HTTP-тесты в main_test.go;
  limiter.go (per-IP лимитер) + mcp.go (MCP-эндпоинт `/mcp`)
- `internal/compress/` — пайплайн: png.go (стратегии, дизеринг), quantize.go
  (median-cut + Ллойд), kd.go (метрика цвета, k-d дерево), jpeg.go (q=52),
  webp.go (libwebp, cgo; webp_nocgo.go — заглушка без cgo)
- `web/` — embed-статика веб-интерфейса + demo/ (пары до/после для слайдера)
  + img/ (фавиконки, og-image), site.webmanifest, robots.txt, sitemap.xml
- `research/` — харнесс tool/, корпус orginal/ + compressed_by_tinypng/
  (не в git), отчёты report.md/report.json, замеры BENCH.md
- `deploy/` — артефакты прода: systemd-юнит, конфиг nginx, ACME-конфиг

## Инварианты (не ломать)

1. Метрика близости цвета — перцептуальная (cbrt ≈ яркость Lab, percLUT в
   kd.go), центроиды Ллойда считаются в ней же. Сырой sRGB даёт «лесенку»
   на тёмных градиентах — проверено на пользователе.
2. Дизеринг: auto = сила 0.6 / clamp 9 (FS, змейка, только RGB с весом
   альфы, error clamp). Амплитуда должна быть сопоставима с шагом палитры
   на рампах, иначе ступени не размываются. `mild` (0.4/6) — спокойный
   режим для UI без зерна.
3. «Лесенка» меряется bias-метрикой (структурная ошибка по окнам против
   оригинала; шум — нулевое среднее), а НЕ оценками vision-модели: она
   видит ужатые копии, и рейтинги между вызовами плавают. Смотреть кропы
   только в натуральном разрешении (vision_analyze region).
4. Рефакторинг обязан быть поведенчески нейтральным: сверять вывод
   байт-в-байт (cmp) по всему корпусу, не выборочно.
5. stdlib-only: новая зависимость — только с явного согласия пользователя.
6. Лимитер по IP: X-Forwarded-For учитывается только за прокси из
   `-trust-proxy` (иначе лимит обходится подменой заголовка); ключ бакета —
   канонический IP, для IPv6 — префикс /64 (иначе лимит обходится перебором
   адресов подсети). MCP-путь обязан брать и per-IP слот, и глобальный
   семафор `s.jobs` (большие PNG жрут ~1 ГБ каждый); слот `s.jobs` держится
   с чтения тела запроса — повторный захват в handleToolCall запрещён
   (дедлок при 4 занятых слотах).
7. Лимит размеров — в ПИКСЕЛЯХ, не только в байтах файла: `MaxPixels`
   (100 Мпикс, compress.go) проверяется по заголовку (DecodeConfig /
   WebPGetFeatures) ДО декода. Файл в килобайты может развернуться в
   гигабайты пикселей («бомба распаковки») — проверка после декода уже
   поздно. Результаты в вебе ограничены и суммарным бюджетом maxStoreBytes.
8. 16-битные PNG — только lossless-переупак: палитра 8 бит теряла бы
   глубину цвета под вывеской «без потерь».
9. Прод: nginx (TLS) → `127.0.0.1:8099` → `tinyimg-web`
   от пользователя `tinyimg`. Бэкенд слушает только loopback — наружу
   торчит 80/443 nginx'а. Параметры `-jobs`/`-store-mb` на этом VPS (2
   ядра, 4 ГБ RAM) занижены (2 и 256): дефолтные 4 сжатия × ~1 ГБ и 1 ГБ
   под результаты — это OOM в общий котёл с соседними сервисами; в юните
   стоит `MemoryMax`, чтобы OOM-счётчик убивал только наш сервис.
   Обновление деплоя — rsync в `/opt/tinyimg/src/` + пересборка
   на сервере (там Go 1.27.3 и libwebp-dev ради cgo/WebP). Домен и
   конкретные пути прода в репозитории не фиксируем — см. `deploy/`
   (обезличенные конфиги с example.com).
10. Статика встроена в бинарь (`//go:embed static`): правка HTML/CSS/JS в
   репозитории не видна пользователю, пока бинарь не пересобран и сервис
   не перезапущен — синхронизация файлов сама по себе меняет только
   исходник на диске. `.webmanifest` Go не знает (`mime.TypeByExtension`
   вернёт пусто) — манифест отдаётся отдельным обработчиком с
   `application/manifest+json`, иначе Chrome отвергнет его молча и
   PWA-иконки не появятся.

## Процесс

- Коммит — только по явной отмашке пользователя; предлагать diff + список
  файлов. Один коммит — одна тема.
- Документация и вывод CLI — на русском.
- Качество глазами пользователя важнее SSIM: жалоба = баг, даже при зелёных
  гейтах. После правок качества показывать кропы и спрашивать вердикт.
