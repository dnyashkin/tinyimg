Компрессор **PNG / JPEG / WebP**, повторяющий зону качества и размера TinyPNG —
но работает **локально**: без загрузки картинок в чужие сервисы и без лимита
5 МБ на файл. Чистый Go (stdlib), ноль внешних зависимостей; единственное
исключение — libwebp через cgo для WebP (сборка без cgo работает, но без WebP).

**[tinyimg.ru](https://tinyimg.ru)** — живой демо-инстанс того же движка.

## Результаты

|---|---|

## Возможности

- **PNG** — квантизация до 256 цветов: median-cut + доводка Ллойда в
  *перцептуальном* пространстве (cbrt ≈ яркость Lab) и дизеринг
  Флойда–Стейнберга с ограниченной амплитудой; lossless-варианты
  (палитра, переупаковка IDAT через zopfli с `--squeeze`) сохраняют
  полное качество.
- **JPEG** — пережатие в зоне качества TinyPNG (q=52, их зона q50–60),
  EXIF и комментарии вырезаются; маленькие и уже оптимальные файлы не трогаются.
- **WebP** — lossless-вход: сравниваются lossless-переупак (method 6) и
  lossy-свип при SSIM ≥ 0.98, берётся меньший (5–10× на сохранённых
  lossless-файлах); lossy-вход — адаптивный q.
- **Метрика «лесенки»** — объективный контроль бандинга на градиентах:
  структурная ошибка ниже TinyPNG в 1.3–1.4 раза.
- **Веб-интерфейс** — drag&drop до 20 файлов, скачивание по одному или zip.
- **MCP-сервер** — `POST /mcp` (Streamable HTTP, JSON-RPC 2.0) для подключения
  к любому MCP-клиенту.
- **Защита** — per-IP rate limit, лимит одновременных сжатий, глобальный
  семафор, бюджет памяти, проверка на «бомбы распаковки» по числу пикселей.

## Установка

```sh
go build -o tinyimg ./cmd/tinyimg
# или сразу:
go run ./cmd/tinyimg --help
```

Сборка с WebP (нужны Go и libwebp):

```sh
go build -o tinyimg ./cmd/tinyimg          # cgo включён по умолчанию
CGO_ENABLED=0 go build -o tinyimg ./cmd/tinyimg   # без WebP
```

## Использование

```sh
tinyimg photo.png                     # один файл -> output/photo.png
tinyimg pics/ -o out                  # папка рекурсивно -> out/
tinyimg pics/ --dither none           # без дизеринга
tinyimg pics/ --json | jq .total      # машинный вывод для скриптов
```

| Флаг | Описание |
|---|---|
| `-o, --output` | каталог назначения |
| `-d, --dither` | `auto` (0.6/9) \| `none` \| `mild` (0.4/6) \| `full` \| `0..1` |
| `--clamp N` | амплитуда дизеринга (auto = 9) |
| `--squeeze` | zopfli-переупаковка PNG: −6…−7% к размеру, ~×25 к времени |
| `-j, --jobs` | параллельность |
| `-q, --quiet` | тихий режим |
| `--json` | вывод JSON для скриптов |
| `-v, --verbose` | подробный вывод + профилирование стадий |
| `--version` | версия |

Коды возврата: `0` — успех, `1` — ошибки обработки, `2` — неверные аргументы.

## Как сжимает

**PNG** — автовыбор:
1. Если цветов ≤ 256 — палитра без потерь (или lossless-переупак, что меньше);
2. Иначе — палитра ≤ 256: median-cut + доводка Ллойда в **перцептуальном**
   пространстве (иначе палитра жадничает цвета из тёмных градиентов, где шаг
   кода заметнее всего), дизеринг Флойда–Стейнберга с ограниченной
   амплитудой (auto = 0.6/уровень 9). Подбор силы — по объективной метрике
   «лесенки» (структурная ошибка по окнам против оригинала; шум — нулевое
   среднее);
3. Lossless-переупак оставляем, если он в пределах +20% от палитрового
   (качество 100% почти даром).

**JPEG** — пережатие в зоне качества TinyPNG (q=52 stdlib, их зона q50–60),
EXIF/комментарии вырезаются. Файлы <100 КБ и уже оптимальные не трогаются
(TinyPNG ведёт себя так же).

## Веб-сервис

```sh
go build -o tinyimg-web ./cmd/tinyimg-web
./tinyimg-web -addr :8080
```

Одна страница: drag&drop до 20 PNG/JPEG/WebP (≤100 МБ каждый, суммарный бюджет
по пикселям — защита от «бомб распаковки»), сжатие тем же движком, что CLI,
скачивание по одному или zip. Результаты живут в памяти час, затем удаляются.
Тесты HTTP-слоя: `cmd/tinyimg-web/main_test.go`.

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-addr` | `:8080` | адрес прослушивания |
| `-rate` | 60 | запросов на IP в минуту (0 — выключить) |
| `-burst` | 30 | размер корзины (батч из 20 картинок проходит целиком) |
| `-conc` | 4 | одновременных сжатий на IP |
| `-jobs` | 4 | глобальный семафор тяжёлых сжатий |
| `-store-mb` | 1024 | бюджет памяти под результаты |
| `-trust-proxy` | — | CIDR прокси, чьему X-Forwarded-For верят (через запятую) |

Защита от перегрузки: token bucket per-IP + лимит одновременных сжатий +
глобальный семафор (большие PNG жрут ~1 ГБ каждый). 429 с честным
Retry-After; ключ бакета — канонический IP, для IPv6 — префикс /64.

### MCP

`POST /mcp` (Streamable HTTP, stateless JSON-RPC 2.0, протокол 2025-03-26) —
тулза `compress_image` (base64 → сжатое изображение base64), подключается к
любому MCP-клиенту как `https://<host>/mcp`. `GET /mcp` отдаёт понятную
страницу с готовым конфигом. Те же лимиты, что на API; ошибки тулзы — в
`result.isError`, 429 — JSON-RPC-ошибкой.

`GET /api/features` → `{"webp": true}` — фронтенд прячет обещание WebP,
если сборка без cgo (кодек недоступен).

## Структура репозитория

```
cmd/tinyimg/       CLI: аргументы, вывод, коды возврата 0/1/2
cmd/tinyimg-web/   веб-сервис: upload → compress → download/zip; limiter.go, mcp.go
internal/compress/ библиотека: PNG-пайплайн, квантизация, k-d дерево, JPEG, WebP
web/               статика веб-интерфейса (go:embed) + demo/ (пары до/после)
research/tool/     харнесс бенчмарка: разбор форматов, PSNR/SSIM, гейты
research/          отчёты, замеры, исходные материалы исследования
deploy/            артефакты прода: systemd-юнит, конфиг nginx, ACME-конфиг
```
