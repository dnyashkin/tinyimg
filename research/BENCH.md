## Наблюдения

- JPEG — 4–8 МБ/с (один проход кодера): 33-мегапиксельные обои за 1.4 с.
- PNG — 0.1–0.5 МБ/с: перебор ближайшего цвета палитры (256×на пиксель) × 8 итераций
  Ллойда × миллионы уникальных цветов. 13.png (фотошная текстура) один = 60% времени.
- Дизеринг включается только при реальной альфе (3.png, 6.png): у «прозрачных»
  10–12.png альфа сплошь непрозрачная, авто-режим его не накладывает.
- Кэш повторных цветов спасает стикеры, но не фотошные PNG (там почти все цвета уникальны).

## Контекст: TinyPNG

- Бесплатный лимит TinyPNG — 5 МБ на файл; всё крупнее — платно. Наши 10–13.png
  (18–21 МБ) и 14.jpg (7 МБ) в бесплатную зону сервиса вообще не попадают.
- По качеству/размеру наш компрессор на 9 парах с TinyPNG проходит оба гейта
  (см. report.md), по скорости работает локально и без лимитов.

## Ускорение: результаты

Цель: быстрее без потери качества. Итог: **342.8 с → 12.7 с wall (×27)**, вывод проверен
поэтапно на байтовую идентичность и гейты.

| шаг | wall | что выяснилось |
|-----|------|----------------|
| исходник (1 поток) | 342.8 с | базовая линия |
| параллельность по файлам (6 воркеров) | 187.7 с | wall ≈ самый тяжёлый файл (13.png) |
| + k-d дерево поиска ближайшего цвета | 187.7 с | **нулевой эффект** — поиск и не был горячей точкой |
| + поразрядное разбиение median-cut + кэш min/max коробок | 157.5 с | 10–12.png: 40 с → 9 с; 13.png всё ещё 151 с |
| + профилирование по стадиям (STAGE_TIMING=1) | — | **93% времени 13.png — попытный lossless-переупак** (flate BestCompression на 71 МБ фотошных данных), чей результат выбрасывался |
| + проба lossless только при ≤4096 цветов и на Default | **12.7 с** | 13.png: 205 с → 12.7 с |

Финальная скорость: 7.8 МБ/с wall (99 МБ → 20.2 МБ, −79.6%). Самый тяжёлый файл — 12.7 с.

Верификация «без потери качества»:
- k-d дерево и параллельность — вывод байт-в-байт идентичен (проверено `cmp`);
- смена разбиения median-cut меняет палитру в пределах шума: гейты против TinyPNG
  **9/9** (размер ≤ +20%, SSIM ≥ tiny − 0.02), дельта «старый → новый вывод»
  PSNR 30–38 дБ / SSIM 0.95–0.99, JPEG не изменились вовсе, глазами бандинга нет.

**Вывод про Rust**: узкие места были алгоритмическими (мёртвая проба lossless-кодирования
и O(n×255) сканы в median-cut) — язык тут ни при чём, Rust не нашёл бы их быстрее.
Оставшееся время — stdlib-кодировщики (zlib/JPEG), они близки к пределу. Go хватает.
